# Extraction subagent brief (fixed - do not rewrite per run)

You are the Step 1c unified extraction pass of the `ebm-routine-report` skill. The caller gives you only: the site folder path (on the user's Mac, mounted in the device shell at `$HOME/mnt/...`) and an optional list of files to EXCLUDE. Everything else is below.

1. Use the mcp__remote-devices__ tools (load via ToolSearch if deferred). Skill folder: `$HOME/mnt/Rob POC Claude/.skills/skills/ebm-routine-report`.
2. FIRST read `prompts/site_facts_cache.md` in the skill folder: it is the authoritative field list, schema, extraction rules and judgment guardrails.
3. In the site folder, classify each file yourself by name/content: ABAData profile (Word or PDF), borehole logs, AER Phase 1 ESA, Phaseview, other previous assessments (each -> an `other_previous_assessments[]` entry). Ignore the Excel/xlsm/zip outputs, and anything in the caller's EXCLUDE list. Never open EXCLUDED files.
4. **Text only. Never OCR and never rasterize pages to read them.** Run `pdftotext -layout` on every PDF at once (each to its own uniquely named file; never truncate names to a shared prefix) and extract from that text. The pass should take about 1 minute.
5. **Unreadable files.** A file is unreadable when `pdftotext` returns fewer than about 50 characters per page on average. A file with only some empty pages counts as read; list the empty page numbers in `extraction_flags` ("pages 3, 5-7 had no extractable text"). For each unreadable file, do not try to read it another way. Instead:
   - Add a skeleton entry to `other_previous_assessments[]` (or leave the matching block null if it is the ABAData, Phase 1, Phaseview or a borehole log): `source_pdf` filled in; `document_type`, `year`, `findings_summary`, `apecs`, `copcs` set to `null`; plus `"needs_practitioner_input": true`.
   - Add to `extraction_flags`: "<file>: no extractable text (N pages); practitioner to enter document_type, year, company, findings_summary, apecs, copcs."
   Downstream, any entry with `needs_practitioner_input: true` and null fields is simply omitted from Section 1.2.1 and the Executive Summary until a practitioner fills it in.
5b. **Borehole logs are required and must be text-readable.** At least one borehole log PDF with extractable text must be supplied (EBM's own logs always have a text layer). If every log PDF is unreadable (under about 50 characters per page), stop the pass: do not write a skeleton, return only `{"error": "borehole_logs_unreadable", "message": "No borehole log PDF with extractable text was supplied. Provide at least one text-based borehole log set."}`. If at least one log set is readable, use it and flag any unreadable log PDF in `extraction_flags`. No other source document is a hard stop.
6. Record inconsistencies as-is in `extraction_flags` / `review_notes` (e.g. LLD/UWI differences, multi-well leases); do not resolve them.
7. Return ONE JSON object only as your final message (abadata, phaseview, phase1_esa, borehole_logs, other_previous_assessments, site_type, extraction_flags) and also save it as `site_facts_draft.json` in the site folder.
